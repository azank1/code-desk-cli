Design note · 2026-09-21 · v0 scope

Coding Desks

An office of coding-harness sessions you already pay for, run from the CLI. One person wears two hats. The tool keeps them apart and makes every handoff between them a file in the repo.

Owner hat: decides scope, priority, acceptance Engineer hat: delivers estimates, evidence, read-backs
Architecture

Files in the repo are the source. Everything else reads them.

office.yaml
The contract. Hats, desks, gates with two-sided deliverables, threads, milestones, cadence, budget.Written once from your paragraph, confirmed by the owner hat, then edited like code.
.office/board.yaml
The state. Each thread's current gate and which deliverables each hat has filed, with evidence and a timestamp.Git-tracked, diffable, receiptable. Progress is derived from this and from git, never typed in.
.office/roles/*.md
One system prompt per desk. Product manager, developer, reviewer by default.Plain markdown. The launcher appends it to the harness's own system prompt.
read and written by
desks.core
Manifest validation, the gate handshake, sync check, inbox derivation.Pure functions over the two YAML files. No network, no keys, no daemon.
desks.meter
Readers for the transcript logs each harness already writes to disk. Attributes turns to desks by working directory and harness, sums per day and per sprint, projects the month.Claude Code: per-turn usage in the project transcript, deduped by request id. Codex: per-turn usage records in the session rollout. Cursor: reader pending.
desks.up
Launcher. One tmux window per desk, the harness started with the desk's role prompt and a session name.Claude Code uses its append-system-prompt flag; Codex takes the role as its first prompt; any other harness runs the command you put in the manifest.
desks.intake
Turns your messy paragraph into office.yaml. It prints a prompt for the harness you are already sitting in, which writes the file. Then desk check validates it.No API key. The harness you pay for does the parsing.
exposed as
desk
The CLI. init · intake · check · board · inbox --as owner|engineer · deliver · status · meter · upInstalled with one uvx coding-desks. Useful with a single desk on day one.
later, not v0
mailbox
A per-desk inbox directory read by a turn-start hook, so a PM desk can hand a thread to a dev desk in another harness.Codex already has a queue command that pushes a message into a running session. Claude Code has hooks. Cursor has hooks.
receipts
The engineer's deliverable at the shipped gate becomes a signed record, so what the owner accepted is what was done.Accepts a receipt produced by an external hook; never signs anything itself.
Journey

From a paragraph to a running office in one sitting

1

Install and initialise inside the repo

uvx coding-desks init writes a template manifest, an empty board and three role prompts. Nothing runs yet.

engineer
2

Paste the messy paragraph

desk intake prints a prompt carrying the manifest schema. You run it in the harness you are sitting in and it writes office.yaml from your own words.

ownerharness
3

Confirm the manifest

desk check validates it and desk board shows threads, milestones and gate contracts. This is the moment the owner hat is forced to exist. Edit the file if it is wrong.

owner
4

Open the office

desk up starts a tmux session with one window per desk, each harness carrying its role prompt and a session name.

engineer
5

Work through gates

A desk that reaches a gate files its half: desk deliver auth-hook engineer estimate --note "2d, touches settle path". The thread waits until the owner files the other half. A desk never guesses past an empty owner column.

engineerowner
6

Read your inbox by hat

desk inbox --as owner lists only pending verdicts. desk inbox --as engineer lists only runnable threads. Same board, two views, one person.

ownerengineer
7

Close the sprint on evidence

desk status shows the sprint window, threads by gate, gates out of sync and who owes what, and spend per desk against budget from the transcript logs. A sprint is a budget window with a milestone in it.

owner
Gate contracts

A gate passes when both columns are filled

GateOwner givesEngineer givesSync check reports
scopescope · priorityestimate · riskswhich hat owes which item
readyverdicttests-green · evidencea verdict filed on no evidence is refused
shippedacceptancedeploy read-back · receipta read-back is a version string, never a status word

The engineer side of every gate is evidence. The owner side is a decision. Timeline drift stops being a feeling: it is the list of gates with one empty column.

Stack

Small on purpose

LayerChoiceWhy
LanguagePython 3.11+, stdlib plus PyYAMLOne uvx install, no compile step, no daemon to ship
Packaginguv, pyproject, console script deskReproducible, publishable later without changes
StateTwo YAML files in the repoDiffable in PRs, no database, no service to keep alive
MultiplexingtmuxAlready on every developer box that runs more than one session
Usage dataHarness transcript logs on diskClaude Code and Codex both record per-turn tokens with the working directory; nothing to instrument
IntakeA printed prompt for the harness you are inNo API key, no second bot, no relay
Testspytest over a temp office and fixture log linesGate handshake and meter dedupe are the two things that must not drift
Deliberately absentdaemon · web UI · SaaS export · API keysEach one is a reason not to install it
v0 ships
  • Manifest with two-sided gate contracts, validated
  • Board with deliver, advance, sync check, two inboxes
  • Meter over Claude Code and Codex logs, per desk, per sprint, monthly projection
  • tmux launcher with role prompts
  • Intake prompt printer
  • Status screen that combines all of the above
After v0
  • Cursor log reader
  • Per-desk mailbox via turn-start hooks and Codex queue
  • Signed receipt as the shipped-gate engineer deliverable
  • Estimate command, enabled only once the meter has a week of history
  • Notion or markdown export of the board, as a view, never the source
